## 요약 결론

현재 행동 판정표를 그대로 유지한다는 조건에서 가장 보수적인 수치 조합은 다음이다.

| 항목 | 조건부 추천 | 신뢰도 |
|---|---|---:|
| 공격 대 특수공격 약화 | `R2 = ceil(specialAttackDamage × 0.25)` | 중간 |
| 특수공격 기본 보너스 | `S1 = +1` | 중간~높음 |
| 단계별 HP·`baseAttack` | `H2` | 중간~높음 |
| `powerGapUnit` | `P25 = 25` | 낮음~중간 |
| 매칭 범위 | `M1 = Child 이상 동일 단계만` | 높음 |

그러나 이 조합도 규칙 확정안은 아니다. 동일 능력·동일 HP의 한 라운드 승패 효용에서 `R1`~`R3`은 공격이 방어를 약하게 지배한다. `R4`로 바꾸면 특수공격이 공격과 방어를 약하게 지배한다. 최종 라운드 HP 우세 상태에서는 `H2`에서도 방어가 모든 상대 행동에 대해 승리를 보장하는 정적 매치업이 73.26%다. 다섯 수치 후보만으로는 이 구조를 제거할 수 없다.

따라서 위 값은 **현재 판정표를 보존해야 할 때의 최소 위험 프로토타입 기준값**이며, 프로덕션 밸런스 확정값은 아니다.

### A.3 분석 방법

1차 전수 계산:

- `R 4 × S 3 × H 2 × P 4 × M 2 = 192`개를 모두 계산했다.
- 정적 모집단은 `(version, digimonId)` 단위 84체다.
- M1은 같은 단계를 양쪽 방향과 자기 대전을 포함해 1,870 ordered matchup으로 계산했다.
- M2는 같은 단계와 인접 단계를 합쳐 4,410 ordered matchup으로 계산했다.
- 각 matchup의 9개 순수 행동 조합을 최대 7라운드까지 정확 계산했다.
- 서로 다른 최대 HP의 판정은 `remainingHpA × maxHpB`와 `remainingHpB × maxHpA`를 비교해 HP 비율과 절대 HP를 분리했다.

`calculatePower()` 이론 커버리지:

- 각 디지몬에 `Strength full 여부 2 × Traited Egg 여부 2 × Effort 0~5의 6 = 24`개 상태를 적용했다.
- matchup마다 `24 × 24` 상태를 전수 계산했다.
- M1은 P 후보마다 1,077,120개 셀, M2는 P 후보마다 2,540,160개 셀이다.
- 이는 가능한 상태 커버리지이며 관측 확률이 아니다.

혼합전략 분석:

- 공격·방어·특수공격 반복, 세 가지 교대, 세 행동 순환, 균형형과 60% 편향형을 합쳐 11개 정책을 비교했다.
- 확률 정책은 seed `20260730`, matchup·정책 쌍당 32회로 실행했다.
- 확률 정책 한 쌍의 결과 수는 `1,870 × 32 = 59,840`이다. 단순 이항 근사 최악 조건의 95% 오차폭은 약 ±0.40%p다.

### B.2 `calculatePower()`의 의미

`digimon-tamagotchi-frontend/src/logic/battle/hitrate.js:84-139`의 실제 식은 다음이다.

```text
power
= basePower
+ Strength full 단계 보너스
+ Traited Egg 단계 보너스
+ min(Effort, 5) × 5
```

단계 보너스는 `Child 5`, `Adult 8`, `Perfect 15`, `Ultimate 25`, `Super Ultimate 25`다. Strength는 `min(5, strength)`가 5일 때만 적용되고 Effort는 최대 5로 제한된다. `traitedEgg` 계산 지원은 있지만 저장소의 운영 writer에서는 해당 필드를 설정하는 경로를 찾지 못했으므로 실제 빈도를 가정하지 않았다.

정적 데이터와 코드상 최대 보너스를 합친 이론 범위:

| 단계 | 정적 `basePower` | 이론 `sourcePower` 범위 |
|---|---:|---:|
| `Child` | 25~30 | 25~65 |
| `Adult` | 40~50 | 40~91 |
| `Perfect` | 85~100 | 85~155 |
| `Ultimate` | 150~180 | 150~255 |
| `Super Ultimate` | 200 | 200~275 |

### B.3 서버 projection과 분리 경계

- `digimon-tamagotchi-frontend/api/_lib/arenaGhostHandlers.js:46-100`은 요청 수신 시각과 snapshot update 시각 중 늦은 시각을 기준으로 슬롯을 projection하고 서버에서 `calculatePower(..., true)`를 호출한다.
- lazy projection은 `digimon-tamagotchi-frontend/api/_lib/urgentCareProjection.js:311-362`를 재사용한다.
- 서버 bundle 진입점은 `digimon-tamagotchi-frontend/src/server/gameProjectionEntry.js:1-16`에 `calculatePower`와 버전 데이터 조회 함수를 노출한다.
- 따라서 인증, 공식 슬롯 projection, `calculatePower`, 서버 권위 스냅샷 패턴은 재사용 가능한 경계다.
- 기존 Ghost Arena의 명중률·단일 요청 판정과 `hitrate.js:31-73`의 `+5/-5` 속성 함수는 이번 `+1/0` 동시 선택 규칙에 재사용하면 안 된다.

확정 계약과 현재 코드의 최소 충돌:

```text
충돌 위치
→ arenaGhostHandlers.js:68-73

현재 코드 근거
→ Ghost 등록은 사망·starter만 차단하며 Child 이상 단계 allowlist는 검사하지 않는다.

확정 계약에 미치는 영향
→ 실시간 M1 참가 검증에서 Child 이상·동일 단계 조건을 별도로 검증해야 한다.

구현 전에 필요한 최소 조정
→ realtime operation의 서버 스냅샷 검증에 실제 단계 키 allowlist와 양쪽 stage equality를 추가한다.
```

또한 Ver.1 `BlitzGreymon` map key의 데이터 `id`는 `BlitzGreymonV1`이다(`v1/digimons.js:723`). 현재 Ghost snapshot은 slot id와 data id가 다르면 거절한다(`arenaDomain.js:191-198`). 정적 밸런스 모집단에는 유효 능력치 개체로 포함했지만, 구현 전에 `(version, digimonId)` 정규화 경계를 확인해야 한다. 이는 밸런스 표본 제외 사유가 아니라 통합 경계 문제다.

## D. 192개 후보 전수 결과와 후보별 결론

192개 규칙 ID는 모두 유일했고 누락은 0개다. 1차 결과의 `candidateResults`는 정적 `basePower` snapshot을 사용했다. 따라서 R·S·H·M 비교에는 직접 사용하고, 실제 육성 보너스에 민감한 P 비교는 별도의 24×24 `calculatePower()` 그리드를 우선했다.

어떤 후보도 “지배 행동 없음” 조건을 충족하지 못했다. 아래 추천은 최종 판정표 재검토 전의 조건부 선택이다.

후보별 수치 결과
→ R1은 공격 counter를 가장 선명하게 만들지만 sourcePower·단계·속성 차이를 완전히 지운다. R2는 공격 우위를 거의 유지하면서 피해 1~2를 남긴다. R3는 무승부 셀을 1.71%로 늘리지만 방어의 구조 문제는 해결하지 않는다. R4는 공격 대 특수공격을 사실상 대칭 교환으로 만든다.

장점
→ R2는 “특수공격 피해의 25%, 올림”으로 설명 가능하고 R1보다 성장 차이를 반영한다.

문제점
→ R2에서도 동일 능력의 한 라운드 효용상 공격이 방어를 약하게 지배한다. R3는 이를 해소하지 못한 채 특수공격의 안전성만 높인다. R4는 특수공격이 공격과 방어를 약하게 지배하는 반대 문제를 만든다.

추천안
→ **R2**.

추천 이유
→ 현 판정표의 역할 설명을 보존하면서 R1의 고정 피해 왜곡과 R3의 추가 변동성을 피하는 최소 위험값이다.

아직 확인할 수 없는 한계
→ 이론 셀의 빈도는 실측 확률이 아니다. 실제 슬롯 분포가 생기면 R2/R3의 체감 차이를 다시 비교해야 한다.

### E.2 한 라운드 구조적 증명

동일 디지몬, 동일 HP, 동일 power의 승/무/패 효용은 R1~R3에서 다음과 같다.

| 내 행동 \ 상대 행동 | 공격 | 방어 | 특수공격 |
|---|---|---|---|
| 공격 | 무 | 무 | 승 |
| 방어 | 무 | 무 | 패 |
| 특수공격 | 패 | 승 | 무 |

공격과 방어를 비교하면 공격은 모든 상대 행동에 방어보다 나쁘지 않고, 상대 특수공격에서는 더 좋다. 따라서 공격은 방어를 약하게 지배한다. 이 결론은 HP·`baseAttack`·`powerGapUnit` 숫자를 바꿔도 공격이 특수공격을 이기고 방어가 공격을 0:0으로 만들면 유지된다.

R4에서는 공격 대 특수공격이 대칭 교환이 된다. 이때 특수공격은 공격과 비기면서 방어를 이기므로 공격과 방어를 약하게 지배한다.

이질적 정적 matchup의 최종 동률 상태에서도 공격이 방어를 약하게 지배하는 비율은 68.07%다. 강한 지배 행동은 검출되지 않았지만, 약한 지배와 안전 행동화만으로도 판정표 재검토 조건을 충족한다.

### E.3 민감도

`R2-S1-H2-P25-M1`에서 한 요소만 바꾼 정적 M1 결과다.

| 변형 | 전체 평균 라운드 | 전체 KO | 전체 무승부 | 특수↔특수 무승부 | 특수→방어 KO |
|---|---:|---:|---:|---:|---:|
| 기준 | 5.557 | 66.67% | 43.29% | 36.15% | 100% |
| 모든 HP -1 | 5.064 | 66.67% | 48.46% | 98.72% | 100% |
| 모든 HP +1 | 5.615 | 66.67% | 42.16% | 36.15% | 100% |
| 모든 `baseAttack` -1 | 6.261 | 62.78% | 44.10% | 53.48% | 87.11% |
| 모든 `baseAttack` +1 | 4.971 | 66.67% | 48.08% | 96.58% | 100% |
| S0 | 5.808 | 63.80% | 45.22% | 53.48% | 87.11% |
| S2 | 5.247 | 66.67% | 50.39% | 96.58% | 100% |
| P20 | 5.547 | 66.67% | 43.17% | 36.58% | 100% |
| P50 | 5.560 | 66.67% | 43.32% | 36.04% | 100% |
| 속성 +1 제거 | 5.845 | 66.67% | 55.44% | 98.93% | 100% |

HP -1, 공격 +1, 속성 제거에서 정수 피해의 라운드 breakpoint가 크게 움직인다. 반면 정적 basePower만으로는 P20~P50 차이가 작다. 이 때문에 H2·S1의 인접값은 배제할 근거가 있지만 P20/P25의 최종 확정에는 실측 슬롯 분포가 필요하다.

## F. 최종 조건부 추천 규칙

```js
const REALTIME_ARENA_BALANCE_CANDIDATE = {
  reducedSpecialDamage(specialAttackDamage) {
    return Math.ceil(specialAttackDamage * 0.25);
  },

  specialAttackBonus: 1,

  hpByStage: {
    Child: 10,
    Adult: 13,
    Perfect: 16,
    Ultimate: 19,
    "Super Ultimate": 20,
  },

  baseAttackByStage: {
    Child: 2,
    Adult: 3,
    Perfect: 4,
    Ultimate: 5,
    "Super Ultimate": 5,
  },

  powerGapUnit: 25,
  eligibleStages: ["Child", "Adult", "Perfect", "Ultimate", "Super Ultimate"],
  matching: "same_stage_only",
};
```

이 값의 사용 조건:

1. 현 행동 판정표를 보존한 프로토타입 비교 기준으로만 사용한다.
2. 행동 판정표를 수정하면 R·S·H 결론을 다시 계산한다.
3. 실제 익명화 슬롯 표본을 확보하면 P20/P25와 R2/R3를 다시 검증한다.
4. M1은 단계 공정성 결과가 충분히 크므로 현재 자료로도 유지할 수 있다.

## G. 재현 가능한 테스트 벡터

### G.1 Adult 중립·동일 power 행동 3×3

입력:

```js
{
  stage: "Adult",
  maxHp: 13,
  baseAttack: 3,
  attackerPower: 50,
  defenderPower: 50,
  attributeAttack: 0,
  specialAttackBonus: 1,
  powerGapUnit: 25
}
```

중간값은 `normal=3`, `special=4`, `reduced=ceil(4×0.25)=1`, `guardPenetration=ceil(4/2)=2`다.

| A 행동 | B 행동 | A 피해 | B 피해 |
|---|---|---:|---:|
| 공격 | 공격 | 3 | 3 |
| 공격 | 방어 | 0 | 0 |
| 공격 | 특수공격 | 1 | 3 |
| 방어 | 공격 | 0 | 0 |
| 방어 | 방어 | 0 | 0 |
| 방어 | 특수공격 | 2 | 0 |
| 특수공격 | 공격 | 3 | 1 |
| 특수공격 | 방어 | 0 | 2 |
| 특수공격 | 특수공격 | 4 | 4 |

### G.2 속성

- Adult Vaccine가 같은 power의 Virus를 공격: `attributeAttack=1`, `normal=4`, `special=5`, R2 약화 `2`, 관통 `3`.
- 역방향 Virus 공격: 별도 감점 없이 `attributeAttack=0`, `normal=3`.
- 어느 한쪽이 `Free`: 양방향 `attributeAttack=0`.

### G.3 power gap 경계

P25에서 공격자와 방어자 sourcePower 차이:

| 차이 | `powerGapAttack` |
|---:|---:|
| -1 이하 | 0 |
| 0 | 0 |
| 24 | 0 |
| 25 | 1 |
| 99 | 1 |
| 100 | 2 |

낮은 쪽의 공격 피해는 감점하지 않는다.

### G.4 HP와 종료 판정

- Adult 중립 특수↔특수: 양쪽이 매 라운드 4 피해를 받아 4라운드에 동시 KO, 무승부.
- Adult HP 13에서 일반 공격 3은 5라운드 KO, 특수 4는 4라운드 KO, 관통 2는 7라운드 KO.
- Child `6/10=60%`와 Adult `8/13≈61.54%`가 최대 라운드에 남으면 절대 HP가 아니라 비율이 높은 Adult 승리.
- Child `7/10=70%`와 Adult `9/13≈69.23%`면 절대 HP가 낮은 Child 승리.
- 양쪽 남은 HP가 0 이하면 항상 동시 KO 무승부이며 HP 비율 판정을 실행하지 않는다.

### G.5 timeout `no_action`

- Adult 공격 대 `no_action`: 공격자는 0 피해, `no_action` 측은 3 피해.
- Adult 특수공격 대 `no_action`: 특수공격자는 0 피해, `no_action` 측은 4 피해.
- `no_action` 대 `no_action`: 양쪽 0 피해.
- 연속 2회 timeout 패배 계약은 라운드 피해와 별도로 적용한다.

### G.6 단계 대표 피해

F절의 H2 중립 단계표를 fixture로 고정한다. 추가로 Child의 이론 경계 `sourcePower 65` 대 `25`, 유리 속성에서는 P25 gap이 1이므로 `normal=4`, `special=5`이고 특수 2회에 HP 10을 KO한다. 이론 커버리지상 한 방 KO는 모든 단계에서 0이다.

P20/P25와 R2/R3를 실제 분포로 다시 판단하려면 최소 100개, 가능하면 각 단계 20개 이상의 battle-ready snapshot을 권장한다.

stage
attribute

## I. 최종 판정

> **행동 판정표 구조 재검토 필요**

근거:

1. R1~R3에서는 동일 조건에서 공격이 방어를 약하게 지배한다.
2. R4에서는 특수공격이 공격과 방어를 약하게 지배한다.
3. 조건부 최선인 H2에서도 최종 HP 우세 측 방어 굳히기가 73.26%의 matchup에서 모든 상대 행동에 승리를 보장한다.
4. 균형형 상대에게 동일 HP 공격 반복 승률이 75.45%로 공격이 지나치게 안전하다.
5. 이 문제는 R·S·H·P·M의 숫자만 조정해서 제거할 수 없다.

아키텍처와 서버 계약은 재논의하지 않았다. 운영 서비스에 접근하지 않았고, 분석 보고서 외 런타임 변경도 하지 않았다.
